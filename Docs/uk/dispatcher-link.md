# Канал диспетчера

[English](../dispatcher-link.md) · **Українська**

Підключає цю станцію FlowStation до ядра [flowstation-platform](https://github.com/hbohatix/flowstation-platform) через QUIC/TLS. Через канал диспетчерська консоль може:

- **викликати групу** — станція встановлює груповий виклик в ефірі й відтворює голос диспетчера;
  аварійний виклик (пріоритет 15) витісняє виклик із нижчим пріоритетом на групі;
- **прослуховувати та записувати кожен груповий виклик** — і локальних, і мережевих (Brew/SIP)
  мовців, лише прийом;
- **бачити мережу** — реєстрації, групи радіостанцій, позиції (LIP), RSSI, виклики, мовців,
  тривоги, а також власний стан станції (час роботи, несучі, навантаження, температура) кожні 10 с;
- **керувати радіостанціями** — DGNA, SDS, kick, запит перереєстрації, запит позиції, бани для всієї мережі.

Станція передає лише кадри ACELP (35 байтів на 60 мс). Кодек працює на платформі.
Версія протоколу 2 (копія в `crates/dispatch-proto`).

## Безпека: трафік диспетчера ніколи не потрапляє в Brew

Виклики диспетчера локальні для цієї соти. Три незалежні шари не пускають їх у Brew/TetraPACK/BrandMeister:

1. **Під час запуску** — якщо будь-яка група з `[dispatcher].gssis` маршрутизується в Brew, канал диспетчера не запускається (сама станція працює далі), а в лозі вказано, які групи конфліктують.
2. **Під час кожного запиту** — група перевіряється знову, коли диспетчер просить передачу (конфігурацію можна змінювати наживо); група, що маршрутизується в Brew, відхиляється з `BrewRoutable`.
3. **CMCE** — жоден виклик на диспетчерській групі ніколи не оголошується в Brew, хоч би хто його почав (диспетчер, локальна радіостанція, радіостанція, що відповідає диспетчеру). Тому Brew також відкидає голос висхідного каналу цього виклику.

Постійний тест проходить повний виклик диспетчера з налаштованим Brew і перевіряє, що до Brew не надходить жодне повідомлення (`test_dispatcher_call_never_reaches_brew`).

## Конфігурація

```toml
[dispatcher]
server = "192.168.1.10:4433"            # адреса QUIC ядра (host:port)
server_name = "core"                    # ім'я в сертифікаті core (за замовчуванням: хост)
ca_cert = "/etc/flowstation/core-cert.pem"  # закріпити сертифікат core (PEM); не задано = системні CA
node_id = "station-01"
token = "change-me"                     # видає консоль (Система → Базові станції)
gssis = [91]                            # групи, які може викликати диспетчер — лише локальні
fallback_issi = 9000001                 # використовується, доки налаштування консолі порожнє
default_priority = 0                    # EN 300 392-2 табл. 14.46
max_tx_seconds = 60                     # обірвати передачу диспетчера після цього часу
link_timeout_ms = 6000                  # завершити передачу диспетчера так швидко після втрати каналу
```

Зробіть диспетчерські групи локальними в `[cell_info]`:

```toml
local_ssi_ranges = [[91, 91]]
```

Сторінка консолі **Система → Базові станції** реєструє станцію, один раз показує її токен,
генерує цей розділ і пропонує сертифікат core (`core-cert.pem`) для `ca_cert`.

Коли `[dispatcher]` увімкнено, відновлення після перезапуску (`[recovery]`) працює завжди: відомі
радіостанції та їхні групи зберігаються в `recovery_cache.json` поруч із конфігурацією.

## Поведінка

| Ситуація | Що робить станція |
|---|---|
| Диспетчер натискає PTT на дозволеній групі, де є слухачі | груповий виклик в ефірі; абонент, що викликає, = ISSI диспетчера; D-SETUP містить запитаний пріоритет |
| PTT відпущено | виклик переходить у hangtime, радіостанції можуть відповісти; їхній голос прослуховується |
| Радіостанція говорить | відмова `FloorBusy` (переривання за EN 300 392-2 §14.5.1.2.1 f — етап 1) |
| Групи немає в `gssis` / немає вільного слоту | відмова `NotAllowed` / `NoResources` |
| Станція не знає жодного слухача групи (наприклад, одразу після перезапуску) | виклик однаково йде в ефір: радіостанції групи чують D-SETUP; виклик не обривається, коли відключається останній відомий слухач |
| Аварійний (або будь-який з пріоритетом 12–15) PTT, коли на групі триває виклик з нижчим пріоритетом | цей виклик звільняється (`PreEmptiveUseOfResource`) і встановлюється новий з пріоритетом диспетчера (EN 300 392-2 §14.8) |
| Перезапуск станції | відновлення після перезапуску завжди ввімкнене, якщо є `[dispatcher]`: відомі радіостанції та їхні групи зберігаються в `recovery_cache.json`, і станція командує їм перереєструватися (D-LOCATION UPDATE COMMAND із запитом звіту груп, EN 300 392-2 §16.4) |
| Немає ISSI диспетчера (налаштування порожнє, резерву немає) | відмова `NoDispatcherIssi` |
| ISSI з консолі збігається з ISSI зареєстрованої радіостанції | станція залишає резервний ISSI і повідомляє консоль про конфлікт |
| Втрачено канал до core | будь-яка передача диспетчера завершується протягом `link_timeout_ms`; перепідключення з наростаючою затримкою |
| Передача довша за `max_tx_seconds` | обрізання, `TxForcedStop` у консоль |
| Канал (повторно) встановлено або `ResyncState` від core | станція надсилає повний стан: `MsRegistered`, `MsGroups` і останню `MsPosition` кожної зареєстрованої радіостанції (`ResyncState` також повторює `SettingsApplied`) |
| Консоль: DGNA / SDS (протокол v1) | виконується через канал керування CMCE (як у дашборді), відповідь `CommandResult`; відповідь радіостанції на DGNA надходить окремо як `DgnaStatus` |

| Консоль: kick / перереєстрація / запит позиції (протокол v2) | CMCE `KickMs`; MM D-LOCATION UPDATE COMMAND із запитом звіту груп; SDS типу 4 з LIP IMMEDIATE LOCATION REPORT REQUEST (TS 100 392-18-1 §6.2.16) |
| Список банів у `Settings` (v2) | забанений ISSI не може зареєструватися чи приєднатися до групи; зареєстровані забанені радіостанції відключаються |
| `MonitorSet { all }` (v2) | прослуховуються всі групові виклики, разом із мережевими (Brew, SIP) мовцями — лише прийом |
| Кожні 10 с | `NodeStatus`: час роботи, несучі, MCC/MNC/LA, зареєстровані радіостанції, виклики, таймслоти, температура CPU |

Без розділу `[dispatcher]` FlowStation поводиться точно так само, як раніше.

Зміни каналу диспетчера: [dispatcher-changelog.md](dispatcher-changelog.md).

## Карта коду

| Частина | Де |
|---|---|
| Протокол (копія `crates/proto` з flowstation-platform) | `crates/dispatch-proto` |
| Розділ конфігурації та перевірка | `crates/tetra-config/src/bluestation/sec_dispatcher.rs` |
| Правила маршрутизації / захист від Brew | `crates/tetra-entities/src/net_dispatcher/routing.rs` |
| Сутність реального часу (виклики, відтворення, сторожові таймери, прослуховування) | `crates/tetra-entities/src/net_dispatcher/entity.rs` |
| Потік воркера (підключення, Hello, heartbeat, налаштування, телеметрія) | `crates/tetra-entities/src/net_dispatcher/worker.rs` |
| Власник виклику в CMCE, відмови, пріоритет | `crates/tetra-entities/src/cmce/subentities/cc_bs/` (`CallOrigin::Network { owner }`, `notify_network_call_rejected`) |
| Параметри QUIC (ALPN, закріплений сертифікат, ім'я сервера) | `crates/tetra-entities/src/network/transports/quic.rs` |

Архітектура й план тестів в ефірі: flowstation-platform `docs/uk/plans/stage0-node-link.md`.
